# Crownfall

Android 向けの「量産型 4X ストラテジー」風ゲーム。**個人利用専用**。

- 中世ファンタジー王国を発展させ、兵を鍛え、ワールドマップで野蛮人や NPC 王国と戦う、見慣れた 4X モバイルの再現
- 同盟には **AI が演じる仲間** がいて、ヘルプ要請・お礼・雑談・DM を通じて「役に立てた」「繋がっている」感がある（無料 API またはローカル LLM、どちらも無しでも動く）
- ショップ・限定パック・ダークパターン風オファーが大量に出てくるが、**決済は 100% 擬似**。購入画面のラグ、「購入が完了しました」演出、レシートメールまで再現しつつ、実際にお金は 1 円も動かない

## 重要な注意
- 本物の決済 SDK（Google Play Billing 等）は一切組み込まない。
- Google / Play / カード会社などのロゴ・名称・固有の配色を模倣しない。決済シートは汎用デザイン。
- 擬似課金 UI はストアポリシーに抵触し得るため **Google Play には公開しない**。サイドロード（APK 直インストール）専用。
- 著作権のあるアセットは使わない。アイコン・図形は自作。

## ビルド
### 前提
- JDK 17 以上（CI は 17、開発コンテナは 21）。Gradle は `./gradlew`（wrapper 8.14.3）を使う。
- 開発コンテナには Android SDK が無い。そのため `:app` は既定では Gradle に含まれず、`:core` / `:ai` のみビルドされる（[docs/02_ARCHITECTURE.md](docs/02_ARCHITECTURE.md) §0）。

### ローカル（JVM モジュール）
```bash
./gradlew :core:test :ai:test ktlintCheck   # テストと静的解析
./gradlew ktlintFormat                      # ktlint の自動整形
./gradlew koverXmlReport                    # カバレッジレポート
```

### Android SDK がある環境
`ANDROID_HOME`（または `ANDROID_SDK_ROOT`）が設定済みなら `:app` は自動で含まれる。明示する場合:
```bash
./gradlew :app:assembleDebug -PwithAndroid=true
```
`-PwithAndroid=false` を付けると SDK があっても `:app` を除外できる。

### APK の入手（GitHub Actions）
1. GitHub のリポジトリで **Actions** タブを開き、対象ブランチの最新 run（`android` ワークフロー）を選ぶ。
2. 下部の **Artifacts** から APK をダウンロードする（保持 14 日）。
   - `crownfall-debug-apk`: debug ビルド（固定の debug 鍵で署名）。
   - `crownfall-release-apk`: release ビルド。リポジトリの Secrets に署名鍵が登録されていればその鍵で署名する。無ければ固定の debug 鍵で署名し、ファイル名が `crownfall-release-debugsigned.apk` になる。
3. zip を展開し、APK を端末へ転送する。
4. 端末で「提供元不明のアプリ」のインストールを許可し、APK を開いてインストールする。

#### 上書き更新の注意
- 同じ署名の APK なら、上書きインストールでセーブデータはそのまま残る。
- 署名が変わると「アプリはインストールされていません」で失敗する。debug と release の APK、または release の署名鍵を登録する前後の APK は署名が異なるので、**先に今のアプリをアンインストール**する（セーブデータは消える。アプリ内のデータは端末内のみで、バックアップは取っていない）。
- debug 鍵は固定（`app/debug.keystore`）なので、debug 同士・release（Secrets 無し）同士なら実行ごとに署名は変わらない。CI のログにある `apksigner` の SHA-256 で確認できる。

## 遊び方（最小ガイド）
1. **城を育てる**: 城内の建物タイルをタップして強化する。建築・研究・訓練には時間がかかり、加速アイテムで短縮できる。倉庫が埋まる前に使う。
2. **兵と英雄**: 兵舎で兵を訓練し、英雄を召喚して部隊を強くする。
3. **マップ**: 野蛮人や砦を討伐し、資源ノードで採集する。襲撃の警告が出たら城の守りを確認する。
4. **同盟**: AI の仲間が助けを求めたり雑談したりする。ヘルプを返し、寄付し、集結に参加して絆を深める。
5. **クエスト・イベント**: 城内の「クエスト」から報酬を受け取る（自動では受け取られない）。毎週月曜に替わる週替わりイベントのランキングは NPC 相手の演出。
6. **ショップ**: 限定パックやガチャ風の演出があるが、**すべて擬似**。購入しても実際のお金は動かない。

## AI の設定
AI の設定が無くても、全機能が定型文（スクリプト）で動く。AI を使うと同盟メンバーの発言が自由な文面になる。設定は **設定画面** で行う。

### Gemini（Google AI Studio の API キー）
1. Google AI Studio で API キーを発行する。
2. 設定画面の Gemini の欄にキーを入力する（端末の Keystore で暗号化して保存される）。
3. 既定のモデルは `gemini-3.1-flash-lite`。変更したければ設定画面で書き換える。
4. 無料枠には 1 分・1 日あたりの上限がある（目安であり、変更され得る）。設定画面の **1 時間あたり / 1 日あたりの予算** で呼び出し回数を絞ると、枠を使い切らない。予算を超えた分と失敗時は定型文に切り替わる。

### Ollama / LM Studio（LAN 内のサーバ）
1. PC で OpenAI 互換のサーバを起動する（例: Ollama は `http://192.168.x.x:11434/v1`、LM Studio は `http://192.168.x.x:1234/v1`）。
2. 設定画面の OpenAI 互換の欄に、そのベース URL とモデル名を入力する。必要ならキーも入力する。
3. 通信先は **プライベート IP（LAN 内）、localhost、`*.local` のみ許可** される。インターネット上の `http://` や公開 IP は拒否される。

### 端末内 LLM（オンデバイス）
通信も料金もかからず、端末の中だけで文章を作る。**アプリにモデルは含まれていない**。設定画面の「端末内 LLM」から使う。
1. LiteRT-LM 形式のモデルファイル（`.litertlm`、または `.task`）を自分で入手する。
2. 設定画面の **モデルファイルを読み込む** でファイルを選ぶ（アプリの内部領域にコピーされる）。または **ダウンロード** に https の URL（必要なら SHA-256）を入れる。途中で止まっても続きから再開できる。
3. ライセンスの同意やログインが必要な配布元は、**先にブラウザでファイルを入手**してから「読み込む」を使う。
4. 目安は RAM 6GB 以上。足りなくても警告が出るだけで使える。「充電中だけ使う」「タイムアウト」も設定できる。
5. 順序は既定で Gemini → 端末内 → OpenAI 互換 → 定型文。モデルが無い・失敗したときは黙って次へ回る。arm64 の端末向け（x86 エミュレータでは動かない）。

## 通知（量産型にうるさい）
アプリを閉じたときに、ゲーム内でこれから起きることを先読みして予約する。設定画面の「通知」で調整できる。
- **強度**: 低 / 標準 / 量産型（既定）。強度ごとに出るカテゴリと 1 時間あたりの上限が決まり、上限を超えた分は「他 N 件のお知らせ」にまとまる。**襲撃の警報は上限の対象外**。
- **襲撃の段階**: 偵察された → 進軍中 → 1 時間前 → 15 分前 → 開始 → 結果。物見の塔の Lv が低いと前の段階は見えない（開始と結果は常に出る）。
- **おやすみ時間**（既定 OFF）: 指定した時間帯は襲撃以外を止める。襲撃も止めるかは切り替えられる。
- 襲撃の各段階とオファーの終了は、**正確なアラーム**（Android 12 以上は設定でアラームの許可が要る場合がある）で予約する。許可が無いときは少し遅れることがある。端末を再起動しても、保存した予定を復元する。
- 復帰の催促（4 時間 / 1 日 / 3 日 / 7 日後）だけは、ゲームの出来事ではないので上限と無関係に予約する。

## 既知の問題
- 実機（複数機種）での動作確認は限定的。エミュレータでは検証できていない項目がある（通知の実表示、権限ダイアログ、Keystore など）。
- 通知は、閉じた時点の状態を先読みして作る予測。オフライン上限（24 時間 + VIP）より先の出来事は予告しない。AI の自由な発言は予測できないので、同盟の要請・DM の通知は同盟システムの予定に基づく。
- 放置時のオフライン進行は上限 24 時間（VIP で延長）。
- release ビルドは R8（縮小）を無効にしている。APK は大きめ。
- 端末内 LLM（オンデバイス）は未対応（インターフェースのみ）。

## 擬似課金の注意
- 実際のお金は一切動かない。本物の決済 SDK も入っていない。決済シートの待ち時間や「購入が完了しました」の演出はすべて作り物。
- Google Play を含む各ストアでは配布しない。サイドロード専用。
- 設定画面の **課金履歴（擬似）** で、擬似購入の記録（日時、商品、金額、きっかけとなったオファーの種類・状況）を確認できる。注文番号はレシートメールに出る。既定では非表示で、確認の上で表示する。この履歴はゲームの進行に影響しない。
- オファーの頻度は設定画面で下げられる（低 / 標準 / 量産型）。

## 開発者向けビルド手順
上の「ビルド」の各節を参照。署名の設定は `app/build.gradle.kts`。release の署名鍵を使うには、CI の Secrets に `RELEASE_KEYSTORE_B64`（keystore を base64 にしたもの）、`RELEASE_STORE_PASSWORD`、`RELEASE_KEY_ALIAS`、`RELEASE_KEY_PASSWORD` を登録する。ローカルでは環境変数 `RELEASE_KEYSTORE_PATH`（keystore のパス）と上の 3 つを設定する。揃っていなければ固定の debug 鍵で署名する。鍵やパスワードをリポジトリやログに書かないこと。
