# 03 AI 同盟メンバー（AI Companions）

## 1. 目的
4X の醍醐味である「同盟の仲間に頼られる／感謝される／雑談する」体験を、**費用 0 円**で再現する。
- 無料 API（Gemini 無料枠、OpenAI 互換の無料エンドポイント）、ローカル LLM（LAN 上の Ollama／LM Studio、将来はオンデバイス）、どれでも差し替え可。
- **API キーが無くても全機能が動く**（Scripted フォールバック）。LLM は「会話の質を上げる追加要素」であり、必須ではない。

## 2. ペルソナ（8 名、`personas.json`）
各ペルソナの属性: `id`, `displayName`, `rank`(R1–R5), `region`, `activeHours`(ローカル時刻帯), `personality`(外向性/面倒見/攻撃性/几帳面/ユーモア 0–1), `speechStyle`(口調サンプル 5 本), `specialty`, `castleLvCurve`, `vipLv`, `spendingHabit`(擬似課金頻度), `favorThresholds`.

## 3. イベント駆動チャット
`core.chat.ChatEvent`（抜粋）:
| イベント | 発火元 | 典型応答 |
| --- | --- | --- |
| `PlayerHelped(count)` | プレイヤーがヘルプを押した | 5〜60 秒遅延で 1〜2 名がお礼 |
| `PlayerDonated(amount)` | 寄付 | リーダーか Lin が反応 |
| `PlayerJoinedRally(result)` | ラリー参加・結果 | 主催者が感謝＋戦果共有 |
| `PlayerCastleUp(lv)` | 城 Lv アップ | 祝福（複数名） |
| `PlayerDefeated(by)` | 襲撃で敗北 | 慰め・助言・増援申し出 |
| `NpcNeedsHelp(persona, kind, amount)` | `AllianceScheduler` | 「石 50k 足りない…誰か…」→ プレイヤーが送る → `NpcThanks` + 好感度 + 同盟ポイント |
| `NpcAsksScout(tile)` | スケジューラ | 偵察して報告 → 感謝 |
| `NpcPurchased(persona, sku)` | スケジューラ（johnny 中心） | 「買っちゃった！」→ 同盟ギフト箱 |
| `Ambient(topic)` | スケジューラ（活動時間帯） | 2〜4 行の雑談（天気、イベント、ランキング、現実の都合） |
| `DailyGreeting` | ログイン時 | 挨拶 |
| `PlayerFreeText(text)` | プレイヤー入力 | 話題と活動時間帯から 1〜2 名が返答 |
| `EventRanking(rank)` | イベント集計 | 「惜しい！」「次は勝てる」 |
| `FavorMilestone(persona, lv)` | 好感度閾値 | DM、ギフト、呼び方変化 |

`AllianceScheduler`（`:core`）は tick 内で時刻・活動時間帯・確率からイベントを生成する（決定論、seed 付き）。オフライン中のイベントも catch-up で生成され、復帰時に「不在中のチャット」として並ぶ。

### 「役に立てた」感の設計
- ヘルプ要請は **プレイヤーが応えられる具体的な行動**（資源送付・偵察・ラリー参加・ヘルプタップ）に限定。応えると必ず感謝が返り、好感度と同盟ポイント、たまに個別ギフト。
- ぽんずは定期的に初心者質問をし、プレイヤーが選択肢（3 択）で答える → 正解/不正解に応じて反応（教える体験）。
- Yuki は復帰時に「不在中にヘルプしてくれてたの気付いた、ありがとう」と **過去のプレイヤー行動を参照**して感謝する（ログを渡す）。
- 好感度 Lv で呼び方が変わる（「領主さん」→ 名前 → あだ名）。

## 4. プロンプト設計（LLM 利用時）
- **system**: 世界設定 + 同盟概要 + 発言するペルソナ全員の定義（活動中のみ）+ 現在状態サマリー（城 Lv、戦力、資源の過不足、直近イベント 5 件、進行中イベント順位）+ 出力ルール。
- **ルール**: 1 行 1〜2 文、日本語、絵文字は人による、ゲーム外の話題は軽く、AI である旨は設定（`revealAi`）に従う、現実のお金の話は「擬似課金」の世界観内で（ジョニーは自慢 OK）、個人情報を聞かない。
- **user**: 直近チャット 20 行 + トリガーイベントの説明。
- **出力**: JSON `{"lines":[{"speaker":"kaede","text":"..."},...]}`。1 リクエストで複数行を得てコスト削減。UI 側で 1 行ずつ数秒間隔・タイピング表示で出す。
- temperature 0.9、maxTokens 300。
- `PromptContextBuilder` は `:core` にあり、純粋な文字列生成（テスト可能）。

## 5. プロバイダと無料枠
| Provider | 無料枠（執筆時点・要確認） | 設定項目 | 備考 |
| --- | --- | --- | --- |
| Gemini API（Google AI Studio で発行） | 無料 tier（RPM/RPD 制限あり） | API キー、モデル名（既定 `gemini-3.1-flash-lite`（2026-10 時点で無料枠の対象。設定で変更可）） | **既定プロバイダ（ユーザー確定）**。設定画面の初期選択は Gemini。コンテナから疎通確認済 |
| OpenAI 互換（Groq） | 無料 tier | base URL、API キー、モデル名 | llama 系。コンテナからは疎通不可だが端末からは可 |
| OpenAI 互換（OpenRouter free モデル） | 無料モデル枠 | 同上 | |
| OpenAI 互換（Ollama / LM Studio） | 完全無料 | LAN の base URL（例 `http://192.168.x.x:11434/v1`）、モデル名 | 自宅 PC で動かす場合。cleartext 許可は該当ホストのみ（`network_security_config`） |
| オンデバイス（MediaPipe LLM Inference, Gemma 3 1B） | 完全無料 | モデルファイル DL（約 0.5GB） | **Phase 2**。端末 RAM 要件あり |
| Scripted | 常時 | なし | 既定・オフライン・フォールバック |

### AiRouter の振る舞い
1. 設定の優先順にプロバイダを試行。タイムアウト 8 秒。429 / 5xx / ネットワーク失敗 → 次へ。
2. 予算: 毎時最大 20 リクエスト、日次 200（設定で変更）。超過時は Scripted。
3. 応答がプレーンテキストなら、テキスト全体を発話者 1 名の 1 行にする。`{` で始まる途中で切れた JSON は "text" の値を抜き出し、できなければ失敗扱い（次のプロバイダへ）にする（M5 REVIEW で決定）。
4. 全失敗 → Scripted。失敗はユーザーに見せない（ログのみ）。設定画面に「直近 24h の LLM 使用回数／失敗回数」を表示。
5. Ambient は 1 回の呼び出しで 3〜5 行を生成し、キューに入れて数分おきに 1 行ずつ放出（人がぽつぽつ話す感）。

## 6. Scripted フォールバックの質
- `templates.json`: `event × persona` ごとに 5〜10 テンプレ。プレースホルダ `{player}` `{resource}` `{amount}` `{castleLv}` `{tile}` `{rank}` `{nickname}`。
- 口調差（語尾、句読点、絵文字頻度）をペルソナ属性から機械的に付与する `StyleApplier`。
- 直近に使ったテンプレは一定回数回避（連続同文を防ぐ）。
- フリーテキスト入力への Scripted 返答はキーワード分類（資源/戦闘/研究/雑談/感謝/質問）→ 分類別テンプレ。十分に「それっぽい」ことを目標にし、LLM があれば自然に置き換わる。

## 7. 安全・プライバシー
- API キーは端末内（Keystore 暗号化）のみ。送信内容はゲーム状態の要約とチャット履歴のみ。端末識別子・連絡先などは送らない。
- 出力の簡易フィルタ（NG ワード表、URL 除去）。
- 「あなた AI？」への対応は設定 `revealAi`（既定: 否定せず曖昧にぼかす）。
- LLM の応答でゲーム状態は変化しない（会話のみ）。ゲーム的効果は常に `:core` のイベントから生じる。
